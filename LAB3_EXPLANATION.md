# PDC50 Laboratory 3: ShopSmart Live Catalog Search Explanation

When a user interacts with the ShopSmart catalog, React's `ProductsPage` sends an HTTP GET request via `api.getProducts(search, { signal })` to Express at `/api/products`, which queries the catalog through Prisma and the database store before returning a formatted JSON payload back to React. The server implements unified live search by evaluating an `OR` condition across both the `name` and `description` fields using case-insensitive partial matching on trimmed query terms. Active product enforcement is strictly maintained by pairing `active: true` with the search filter at the root of the query, guaranteeing that inactive items are excluded even if their text matches. On the client side, React coordinates live searching through a debounced effect that triggers server requests as the user types or clears the search box without requiring manual page reloads. Stale response race conditions are prevented by aborting previous in-flight requests using an `AbortController` and guarding state updates with sequential request identifiers. The user interface clearly separates request lifecycle states, presenting an explicit loading indicator during retrieval, an empty-result prompt when no products match, and a clear error notification with a retry button upon server failure. Category choices remain permanently stable because the full category list is preserved from the active catalog rather than derived from shrinking search results. Category filtering and numeric price sorting work together in sequence on the current server response, filtering matching items by category and sorting them deterministically without mutating the source array.
